# Sessão 2026-05-03 — Sprint 1 · Fundação Funcional

## O que foi feito

### 1. Schema Prisma — migrations Sprint 1
- Adicionados `nivelamentoConcluido` e `nivelamentoPath` ao model `Profile`
- Adicionados `title`, `tags` (Json), `subject` ao model `Annotation`
- Adicionados `type`, `source`, `topicId`, `status` ao model `Question`
- Novo model `TopicRead` com relações em `User` e `Topic`
- `npx prisma generate` rodado — Prisma Client atualizado

### 2. Migration aplicada manualmente (sprint1_manual.sql)
- Script em `prisma/migrations/sprint1_manual.sql`
- Criou todas as tabelas da aplicação (users, profiles, topics, subscriptions, etc.)
- NÃO tocou nas tabelas ETL (legal_articles, question_bank, ingestion_run, etc.)
- FK entre simulado_questions/user_question_answered → questions omitida propositalmente
  (incompatibilidade de tipos: questions.id é UUID no ETL, demais tabelas usam TEXT/Prisma padrão)
- Aplicado em **staging** e **live** com sucesso

### 3. M1 Onboarding — reimplementado
- `POST /onboarding/complete`: body com `academicPhase` + `dailyStudyMins`, seta `nivelamentoPendente: true` para TODOS, calcula `flow` e `nivelamentoPath`
- `POST /onboarding/diagnostic/complete`: `nivelamentoPendente: false`, `nivelamentoConcluido: true`
- `POST /onboarding/diagnostic/dismiss`: `nivelamentoPendente: false`, `nivelamentoConcluido` mantém valor (idempotente)
- Rotas antigas (GET /state, PUT /step, POST /complete sem body) removidas

### 4. M3 Manual — completo
- `POST /manual/topics/:id/read`: upsert idempotente em `TopicRead`
- `GET /manual/topics`: retorna `progress.readCount` e `progress.totalTopics` por `lawCode`
- `GET /manual/topics/:id`: retorna `isRead: boolean` para o usuário
- `GET /manual/search`: resultados unificados de topics (ILIKE) + legal_articles (BM25) com campo `source`

### 5. M2 Dashboard — completo
- `GET /dashboard`: agora retorna `oabMode`, `nivelamentoPendente`, `dailyProgress` (questionsAnsweredToday, topicsReadToday, dailyGoalMins)
- `GET /dashboard/revision-cards`: agrupa SimuladoQuestion das últimas 2 semanas por subject, calcula errorRate, ordena por errorRate DESC
- `GET /dashboard/performance`: totalAnswered, globalAccuracyRate, oabBaseline: 0.60, bySubject

### 6. M6 Anotações — completo
- `POST /annotations`: aceita `title`, `tags` (array), `subject`
- `PUT /annotations/:id`: atualiza todos os campos novos sem perder os outros
- `GET /annotations`: filtros `subject`, `tag` (JSON contains via raw), `q` (ILIKE em title/content), `topicId`

### 7. Users — completo
- `PUT /users/profile`: aceita `academicPhase`, atualiza `nivelamentoPath` automaticamente
- `GET /users/profile`: já retornava o profile completo; `nivelamentoPendente` disponível

### 8. Observação de ambiente
- `.env` criado em `back/lcf-backend/` com credenciais de staging
- `prisma migrate dev` não funciona em terminal não-interativo — usamos `prisma db execute` com SQL manual
- `prisma db push` era perigoso (teria dropado tabelas ETL) — evitado
