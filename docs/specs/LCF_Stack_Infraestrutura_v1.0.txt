1. Visão Geral
Este documento consolida as decisões de stack e infraestrutura para o MVP da plataforma LCF, um aplicativo EdTech jurídico mobile-first focado em estudantes de Direito e candidatos ao Exame da OAB.

Escopo: listar TODAS as tecnologias a serem utilizadas no desenvolvimento do app. Decisões de arquitetura de dados, pipelines de IA e nuances de estrutura serão documentadas em documentos complementares.

Constraint: desenvolvimento em ~2 meses, custo operacional baixo (100-500 assinantes), validação de mercado e funcional.

Princípio: stack simples, agnóstica onde possível (especialmente na integração de IA), com escalabilidade futura viável sem reescrita.

2. Frontend
Filosofia: codebase único para iOS, Android e Web (mobile-first).

2.1 Framework
Tecnologia

Detalhes

Flutter

Versão: 3.x (stable)

Plataformas: iOS, Android, Web (Flutter Web)

Justificativa: codebase único, mobile-first, rápido para MVP, excelente performance em 4G

2.2 Gerenciamento de Estado
Tecnologia

Detalhes

Riverpod

Versão: 2.x

Modelos: StateNotifier, FutureProvider, StreamProvider

Justificativa: moderno, tipado, testável, sem boilerplate excessivo

2.3 Cache e Persistência Local
Tecnologia

Detalhes

Isar

Versão: 3.x

Uso: cache local do Manual (conteúdo jurídico), suporte offline

Capacidades: full-text search, queries complexas, sincronização incremental

Justificativa: mais rápido que Hive, suporta busca full-text nativa (requisito RF32)

2.4 Cliente HTTP
Tecnologia

Detalhes

Dio

Versão: 5.x

Interceptors: JWT auth, retry automático, logging, timeout

Justificativa: padrão em Flutter, suporta uploads/downloads, tratamento robusto de erros

3. Backend
Filosofia: monolito modular, fácil de manter, escalável para microserviços no futuro.

3.1 Runtime e Linguagem
Tecnologia

Detalhes

Node.js

Versão: 18.x LTS ou 20.x

Linguagem: TypeScript (strict mode)

Justificativa: tipagem forte, ecossistema maduro, reduz bugs em produção, velocidade no MVP

3.2 Framework Web
Tecnologia

Detalhes

Fastify

Versão: 4.x

Middleware: plugins nativos para auth, CORS, compression

Justificativa: 2-3x mais rápido que Express, schema validation nativo via JSON Schema, menor footprint

3.3 Arquitetura
Padrão: Monolito Modular

Estrutura: /src → /modules → /auth, /onboarding, /dashboard, /manual, /tutor-ia, /simulados, /anotacoes

Cada módulo: rota → controller → service → repository

Vantagem: fácil de manter no MVP; extração de serviços isolados viável sem refatoração major

4. Banco de Dados
4.1 Banco Principal
Tecnologia

Detalhes

PostgreSQL

Provedor: Supabase (BaaS gerenciado)

Versão: 14.x ou 15.x

Limites (Free Tier): 500 MB storage, 50k MAU — gatilho real de upgrade esperado pelo storage (~400 MB) antes de atingir o limite de MAU

Incluso no Supabase: Auth (Supabase Auth), Storage (S3-like), Realtime, REST API automática

Justificativa: elimina 2-3 semanas de setup; suficiente para 100-500 assinantes; migração futura viável

4.2 Banco Vetorial (RAG Futuro)
Tecnologia

Detalhes

pgvector

Tipo: Extensão PostgreSQL

Uso: armazenar embeddings de conteúdo jurídico para busca semântica

Integração: no mesmo PostgreSQL do Supabase (sem infra adicional)

Justificativa: evita adicionar Pinecone/Weaviate no MVP; escalável com RAG próprio depois

4.3 Corpus Jurídico — ETL LexML

Pipeline de ingestão do Vade Mecum via LexML (lexml.gov.br) para popular a tabela legal_articles no Supabase.

Escopo: 9 diplomas prioritários OAB — CF/88, CC, CP, CLT, CPC, CPP, CTN, CDC, Estatuto da OAB (~50k artigos)

Estimativa: 2-5 dias de engenharia incluindo validação

Especificação técnica detalhada: LCF_ArquiteturaIA_MVP (seção 2.2)

Status: frente de trabalho a especificar — estrutura (script avulso, job no Railway ou processo manual) a definir em etapa posterior. Pré-requisito para funcionamento do Tutor IA (M4).

5.4 CI/CD
Serviço

Detalhes

GitHub Actions

Integração: Railway deploy automático via webhook

Justificativa: nativo no GitHub, gratuito, suficiente para MVP

5.5 Monitoramento e Logging
Serviço

Detalhes

Sentry

Plano: Free (5k eventos/mês)

Cobertura: frontend (Flutter) + backend (Node.js)

Captura: exceções, erros de rede, crashes, performance

Justificativa: confiabilidade crítica; alertas em tempo real

5.6 Analytics
Serviço

Detalhes

Umami

Tipo: Open-source, self-hosted

Hospedagem: container no Railway (sem custo adicional)

Conformidade: LGPD-friendly (sem cookies de rastreamento)

Justificativa: alternativa leve a Google Analytics, privacy-first, custo zero

5.7 Cache e Sessão (Redis)
Serviço

Detalhes

Upstash (Redis Serverless)

Plano: Free ($0) — 10k comandos/dia, 256 MB storage

Uso: sessão do Tutor IA (histórico das últimas 8 mensagens, TTL 4h), rate limiting por plano (Free: 20 msgs/dia; PRO: 200 msgs/dia via contador com TTL 24h), budget de tokens por sessão

Chave de sessão: UUID gerado no client — sem vínculo obrigatório ao user_id (simplifica LGPD)

Upgrade: Upstash Pay-as-you-go ao ultrapassar free tier

Justificativa: serverless, zero configuração, TTL nativo, sem custo fixo no MVP; evita manter instância Redis dedicada

5.8 Push Notifications
Serviço

Detalhes

OneSignal

Plano: Free ($0) — até 10k subscribers

Uso: notificações push iOS/Android via Flutter; lembrete diário de streak com horário configurável pelo usuário (T21); toggle geral on/off por usuário

Integração: SDK Flutter nativo; usa FCM (Android) e APNs (iOS) por baixo — sem necessidade de configurar FCM diretamente

Justificativa: segmentação, agendamento e gestão de tokens prontos — elimina dias de implementação no backend; free tier suficiente para MVP; alinhado com T21 (Especificação v5.0)

6.2 Pagamento
Serviço

Detalhes

RevenueCat

Plano: Gratuito até $2.500 MRR

Funcionalidades: abstrai Apple IAP (iOS) e Google Play Billing (Android) em uma única API; webhook de confirmação de compra para ativação do plano PRO no backend

Comissão: 0 custos fixos até $2.500 MRR; acima disso, 1% da receita

Webhooks: confirmação de compra → API backend → ativação do plano PRO

Justificativa: obrigatório para aprovação na App Store e Google Play — assinaturas digitais em apps mobile devem passar pelo sistema de IAP nativo de cada loja; Stripe direto resulta em rejeição. SDK Flutter disponível.

Nota — Web: para eventuais assinaturas via WebApp, avaliar Stripe como processador complementar (fora do escopo MVP mobile).

6.3 LLM para Tutor IA — Estratégia Híbrida
Serviço

Detalhes

Sabiá-4 (Maritaca AI) — LLM Primário

Provedor: Maritaca AI

Custo: R$ 1,00/1M tokens input | R$ 4,00/1M tokens output

Contexto: 128k tokens

Uso: ~75% das queries — definições de conceitos jurídicos, explicação de artigos recuperados via Tool Use, relações entre institutos jurídicos

Justificativa: especializado em Direito brasileiro, custo ~16x menor que Claude Sonnet 4.6, baixa latência; suporta Tool Use nativamente via API compatível com padrão OpenAI (parâmetros tools e tool_choice: "required")

Claude Sonnet 4.6 (Anthropic) — LLM Secundário

Provedor: Anthropic

Modelo: claude-sonnet-4-6

Custo: $3,00/1M tokens input | $15,00/1M tokens output

Contexto: 200k tokens

Uso: ~25% das queries — análise pós-erro de simulado (PRO), jurisprudência controversa, doutrina divergente, raciocínio de alta complexidade

Justificativa: raciocínio complexo, pedagogia aprofundada, context window superior para bundles de simulado

Arquitetura: ambos implementam a interface LLMAdapter (llm.interface.ts) — loop agêntico de Tool Use idêntico, sem bifurcação de lógica no backend. Roteamento via llm.router.ts por modo e complexidade da query.

Custo estimado MVP: ~$1–32/mês dependendo do volume (30–200 MAU ativos no Tutor)

Requisitos: RF40, RF41, RF42, RF43, RF45

6.4 Transcrição de Voz

Fora do escopo MVP. Entrada por voz no Tutor IA foi avaliada e excluída por custo/valor desfavorável no estágio inicial.

Previsão: v1.1 — Whisper API (OpenAI), integração Flutter audio plugin → upload → API Whisper → texto. Pipeline de texto do Tutor não muda ao reintroduzir.

8. Roadmap de Escalabilidade
8.1 Quando Migrar (500+ assinantes)
• Supabase Free → Pro ($25/mês): aumento de quotas, suporte prioritário

• Railway Hobby → Pro: escalação automática, mais RAM/CPU

• Claude API: adicionar cache de respostas frequentes (Redis ou memória local)

• Umami: upgrade para plano pago ou migrá-lo para servidor dedicado

8.2 Quando Migrar para AWS (1000+ assinantes ou demanda por infra própria)
• Supabase → RDS PostgreSQL gerenciado (AWS)

• Railway → ECS/Fargate (AWS): containers orchestrados

• Cloudflare: manter (agora com plano Pro ou Enterprise conforme necessário)

• S3 + CloudFront: assets de armazenamento e CDN

• GitHub Actions → AWS CodePipeline/CodeDeploy

• ElastiCache (Redis): cache distribuído para respostas de IA e sessões

• Datadog ou New Relic: monitoramento enterprise (substitui Sentry)

8.3 Arquitetura de IA Futura (RAG e LLM)
• RAG próprio com pgvector: busca semântica de conteúdo jurídico curado

• Fila de jobs (Bull/BullMQ): processamento assíncrono de embeddings e análises

• LLM agnóstico: adapter permite trocar de Claude → GPT-4 → modelo próprio sem refatoração

9. Notas Importantes
Stack Agnóstica:

A integração do LLM é feita via adapter — a troca de Claude para outro provedor (OpenAI, Google, modelo próprio) não requer refatoração do código principal, apenas substituição do adapter e ajustes de chamadas API.

Offline-First (Manual):

O conteúdo do Manual do Direito é cacheado localmente em Isar. Sincronização incremental garante que atualizações de conteúdo são baixadas progressivamente, sem bloquear o acesso offline.

LGPD e Privacidade:

Todas as integrações respeitam LGPD. Consentimento explícito para compartilhamento de dados com IA é obrigatório. Umami é privacy-first (sem cookies de rastreamento).

Performance:

Requisito RNF05: carregamento em < 2s em conexão 4G. Fastify + Isar local + Cloudflare CDN garantem isso. Testes contínuos via Lighthouse/Webview.

Testes e Qualidade:

GitHub Actions executa testes automaticamente a cada push. Sentry captura erros em produção em tempo real. Ambientes: dev (local), staging (Railway), production (Railway).

Segredos e Configuração:

Variáveis de ambiente (.env): API keys (Claude, Whisper, Stripe), credenciais DB, etc. Railway suporta secrets nativamente. Nunca commitar secrets em Git.
